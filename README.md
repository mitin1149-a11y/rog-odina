# Рог Одина

Учебный сайт: слушает музыку через микрофон, показывает 10-полосный эквалайзер и сцену у костра, где викинги танцуют в такт. Название песни сайт не распознаёт. Всё работает в браузере: нет сервера, API-ключей и платных сервисов.

Стек: Vite, чистый JavaScript, Three.js, Web Audio API.

## Запуск

Нужен [Node.js](https://nodejs.org) версии 18 или новее.

```bash
npm install
```

```bash
npm run dev
```

Откройте `http://localhost:5173` и нажмите на щит "Слушать". Браузер спросит разрешение на микрофон.

Если PowerShell пишет "Невозможно загрузить файл npm.ps1, так как выполнение сценариев отключено", запускайте через `npm.cmd`: `npm.cmd install`, `npm.cmd run dev`. Либо используйте обычную командную строку (cmd), там ошибки нет.

Сборка для публикации:

```bash
npm run build
```

Готовый сайт появится в папке `dist`. Посмотреть его локально: `npm run preview`.

### Микрофон работает только на localhost или по HTTPS

Это правило браузеров, а не сайта. `http://localhost:5173` подходит. Если открыть сайт по адресу вида `http://192.168.1.35:5173` с телефона, микрофон не включится: для телефона используйте версию на GitHub Pages (там HTTPS).

### Проверка без микрофона

Добавьте к адресу `?demo` или `?demo=140`: вместо микрофона сайт сам синтезирует бит с заданным темпом (по умолчанию 120 BPM). Звук демо, как и звук микрофона, в динамики не выводится, только в анализатор.

Определение темпа можно проверить и без браузера:

```bash
node scripts/test-tempo.mjs 128
```

Скрипт синтезирует 20 секунд бита, считает спектр так же, как это делает браузер, и сравнивает найденный темп с заданным.

## Что умеет

- Кнопка-щит "Слушать"/"Стоп". Слушает без ограничения по времени.
- Индикатор "Тишина"/"Звучит музыка", громкость в дБ, примерный темп в BPM, мигающая точка на каждой доле.
- Выбор микрофона (список появляется, если микрофонов больше одного), ползунок чувствительности.
- Эквалайзер на 10 полос: 32, 64, 125, 250, 500 Гц, 1, 2, 4, 8, 16 кГц. Столбики в виде пламени с рунами, плавный спад, голубые пиковые отметки.
- Под каждой полосой ползунок ±12 дБ. Пресеты "Ровно", "Бас", "Рок", "Вокал", "Боевой рог". Настройки сохраняются в localStorage.
- Круговой спектр и волна вокруг щита.
- 3D-сцена: ночной фьорд, драккар, длинный дом, костёр, туман, северное сияние, 3 или 5 викингов.
- Переключатель "Анимация вкл/выкл" и выбор качества графики. На слабых устройствах качество снижается автоматически.
- Один-проводник: летает по экрану, здоровается, проводит экскурсию по управлению и отвечает на вопросы в чате справа.

## Один-проводник (чат-бот)

Код лежит в `src/odin/`.

- `odinSvg.js` - рисунок Одина в SVG: шляпа странника, повязка на глазу, борода, копьё Гунгнир и вороны Хугин и Мунин.
- `OdinGuide.js` - полёт по экрану, облачко с репликами, экскурсия и чат.
- `knowledge.js` - база знаний: около 30 тем с ключевыми словами и ответами.

**Полёт.** Один выбирает случайную точку на экране и летит к ней: скорость плавно растёт и падает у цели, пауза 1,5-5 секунд, новая точка. Под музыку он покачивается быстрее и подпрыгивает на долях. В "Настройках" есть переключатель "Один летает по экрану": если выключить, он сидит у правого края. Можно и попросить в чате: "не летай" или "летай".

**Приветствие и экскурсия.** При первом заходе Один здоровается и предлагает показать управление. Во время экскурсии он подлетает к каждому элементу (щит, статус, эквалайзер, ползунки, пресеты, настройки, сцена) и подсвечивает его. Повторно гостей он просто приветствует. Отметка о первом визите хранится в localStorage.

**Чат.** Щелчок по Одину открывает чат в правой колонке (на телефоне на весь экран). Бот работает без ИИ и без интернета: вопрос приводится к нижнему регистру, разбивается на слова, и каждое слово сравнивается с основами слов тем ("эквалайз" ловит "эквалайзер", "эквалайзера"). Побеждает тема с наибольшим счётом: совпавшее слово даёт 1 балл, фраза из нескольких слов 2 балла, общие слова вроде "что такое" и "зачем" полбалла. Если ничего не совпало, Один предлагает темы, о которых знает. Под ответами бывают кнопки: начать слушать, открыть настройки, включить пресет, задать следующий вопрос.

Новую тему можно добавить в массив `TOPICS` в `knowledge.js`: `id`, список основ `stems` и текст `answer`. Проверка базы знаний:

```bash
node scripts/test-odin.mjs
```

Скрипт задаёт 34 типичных вопроса и проверяет, что каждый попал в нужную тему.

## Как устроен анализ звука

Этот раздел для защиты проекта. Код лежит в `src/audio/`.

### 1. Захват звука

```
микрофон → getUserMedia → MediaStreamAudioSourceNode → AnalyserNode
```

`AnalyserNode` не подключён к `audioContext.destination`, поэтому звук не идёт в динамики и не возникает свиста (акустической обратной связи).

В `getUserMedia` выключены `echoCancellation`, `noiseSuppression` и `autoGainControl`. Эти фильтры сделаны для речи: шумоподавление срезает тарелки, а автоусиление выравнивает громкость, и тогда доли теряются.

### 2. Спектр

`AnalyserNode` делает быстрое преобразование Фурье (БПФ) по окну из 4096 отсчётов. На выходе 2048 чисел: громкость в децибелах для каждой частоты. Шаг между соседними частотами (бинами):

```
шаг = частота дискретизации / 4096 = 48000 / 4096 ≈ 11,7 Гц
```

Окно 4096 выбрано, чтобы различить нижние полосы: полоса 32 Гц занимает всего 2 бина. При окне 1024 шаг был бы 47 Гц и полосы 32 и 64 Гц слились бы.

Сглаживание анализатора выключено (`smoothingTimeConstant = 0`): для поиска долей нужны резкие перепады, а плавность столбикам добавляется отдельно.

### 3. Десять полос эквалайзера

Каждая полоса - октава вокруг центральной частоты `fc`: от `fc/√2` до `fc·√2`. Для полосы 1 кГц это 707-1414 Гц.

Для каждой полосы:

1. децибелы каждого бина переводятся в мощность: `p = 10^(дБ/10)`;
2. мощности усредняются (децибелы нельзя усреднять напрямую, это логарифмы);
3. среднее переводится обратно в дБ, прибавляется усиление полосы (±12 дБ) и общая чувствительность;
4. диапазон от -90 до -30 дБ отображается в высоту столбика от 0 до 1.

Ползунки ±12 дБ меняют только отображение. Звук они не меняют, потому что звук никуда не выводится.

Столбик поднимается мгновенно, а опускается со скоростью 1,3 высоты в секунду. Пиковая отметка висит 0,8 с, потом медленно падает.

### 4. Громкость и "тишина / музыка"

Громкость считается по форме волны как среднеквадратичное значение (RMS) и переводится в дБ относительно максимума (дБFS):

```
RMS = √(сумма x² / N),   уровень = 20·log10(RMS)
```

Состояние переключается с гистерезисом: "Звучит музыка" включается, если уровень выше -50 дБ дольше 0,3 с, а выключается, если ниже -56 дБ дольше 1,5 с. Без разницы порогов и задержек индикатор мигал бы на каждой паузе в песне.

### 5. Поиск долей (ударов)

Доли ищутся по басу, 35-160 Гц: там бочка и бас-гитара.

1. **Спектральный поток.** Для каждого бина баса берётся прирост амплитуды по сравнению с прошлым кадром. Положительные приросты складываются. Удар бочки даёт резкий скачок потока.
2. **Адаптивный порог.** За последнюю секунду считаются среднее и стандартное отклонение потока. Удар засчитывается, если поток больше `среднее + 1,5·σ`. Порог сам подстраивается под громкость и жанр.
3. **Защита от дребезга.** Между ударами не меньше 0,25 с (это максимум 240 ударов в минуту).

### 6. Темп (BPM)

Темп считается автокорреляцией огибающей потока:

1. поток за последние 8 секунд пересэмплируется на равномерную сетку 100 точек в секунду;
2. из сигнала вычитается среднее;
3. для каждого сдвига от 0,33 до 0,86 с (это 180-70 BPM) считается, насколько сигнал похож сам на себя со сдвигом. Пик похожести даёт длину доли;
4. добавляется похожесть на двойном сдвиге (у музыки период повторяется и через две доли) и мягкий вес в пользу темпов около 120 BPM;
5. положение пика уточняется параболой по трём соседним точкам, чтобы получить дробное значение;
6. темп пересчитывается дважды в секунду и сглаживается.

`BPM = 60 · 100 / сдвиг_в_точках`

Ограничение: у быстрых треков (170+ BPM) темп может определиться вдвое меньше, например 87 вместо 174. Это классическая ошибка "октавы темпа", её делают и коммерческие программы.

### 7. Часы долей

Отдельные удары бывают пропущены или лишние, а танцу нужен ровный ритм. Поэтому есть "часы": фаза от 0 до 1 растёт со скоростью `BPM/60` в секунду, каждый переход через 1 считается долей. Когда находится настоящий удар, фаза подтягивается к нему на 35% ошибки. Так устроена фазовая автоподстройка частоты (ФАПЧ).

Сильная доля: каждая четвёртая (первая в такте 4/4) или удар, который на 35% громче среднего удара в треке.

### 8. Как музыка управляет сценой

| Данные анализа | Что происходит в сцене |
|---|---|
| нет музыки | викинги стоят у костра (анимация Idle) |
| громкость (энергия 0..1) | размах движений, яркость огня, скорость северного сияния |
| фаза доли | викинги пружинят вниз на каждой доле, качают корпусом на две доли |
| темп | скорость танца |
| сильная доля | притоп ногой, топор вверх, выброс искр, вспышка костра, иногда клич (анимация Cheer) |

## Как устроена 3D-сцена

Код в `src/scene/`:

- `VikingScene.js` - рендерер, камера (медленно облетает костёр), свет луны, качество графики.
- `environment.js` - рельеф фьорда по функции высоты с шумом, вода (`Water` из three.js с отражениями, на слабых устройствах простой металл), длинный дом, драккар, ели, северное сияние (шейдер), туман.
- `fire.js` - пламя и искры на частицах, точечный свет с мерцанием и тенями.
- `vikings.js` - загрузка моделей и танец.

У модели KayKit нет танцевального клипа. Поэтому танец собран из клипа Idle и процедурных поворотов костей поверх него: бёдра, позвоночник, голова, руки, ноги. Каждый кадр кости сначала возвращаются в исходное положение, потом клип ставит позу, потом добавляются повороты от музыки.

Качество "Высокое": 5 викингов, тени, отражения в воде. "Низкое": 3 викинга, меньше частиц, без теней. В режиме "Авто" качество выбирается по устройству и снижается, если в первые секунды меньше 28 кадров в секунду.

## Публикация на GitHub Pages

Сайт статический, его можно бесплатно выложить на GitHub Pages. GitHub сам соберёт его при каждом изменении.

1. Зарегистрируйтесь на [github.com](https://github.com) и установите [Git](https://git-scm.com/download/win). После установки перезапустите терминал.
2. Создайте на GitHub новый репозиторий, например `rog-odina`. Ничего в него не добавляйте (без README и .gitignore).
3. В папке проекта выполните по очереди (вместо `ЛОГИН` ваш логин на GitHub):

```bash
git init
```

```bash
git add .
```

```bash
git commit -m "Рог Одина"
```

```bash
git branch -M main
```

```bash
git remote add origin https://github.com/ЛОГИН/rog-odina.git
```

```bash
git push -u origin main
```

4. На GitHub откройте репозиторий → Settings → Pages. В поле Source выберите **GitHub Actions**.
5. Откройте вкладку Actions: через 1-2 минуты сборка "Публикация на GitHub Pages" станет зелёной.
6. Сайт будет по адресу `https://ЛОГИН.github.io/rog-odina/`. Там HTTPS, так что микрофон работает и на телефоне.

Если сборка не запустилась сама, на вкладке Actions выберите workflow и нажмите "Run workflow". После следующих изменений достаточно `git add .`, `git commit -m "..."`, `git push`.

Пути в проекте относительные (`base: './'` в `vite.config.js`), поэтому сайт работает с любым именем репозитория.

## Свои модели викингов (Sketchfab + Mixamo)

С проектом идёт персонаж KayKit: он мультяшный, но лицензия CC0 позволяет его выкладывать без условий. Чтобы викинги были реалистичнее, можно подставить свою модель. Код подхватит её сам, если положить файлы в `public/assets/models/custom/`.

Нужны бесплатные аккаунты на Sketchfab и Adobe (для Mixamo).

1. **Модель.** На [sketchfab.com](https://sketchfab.com) найдите "viking", включите фильтр Downloadable и проверьте лицензию: подходят CC0 и CC Attribution (CC-BY). Скачайте в формате FBX или OBJ (с текстурами).
2. **Скелет.** Откройте [mixamo.com](https://www.mixamo.com), нажмите Upload Character, загрузите модель, расставьте маркеры (подбородок, запястья, локти, колени, пах) и дождитесь автоматической привязки скелета.
3. **Сама модель.** Нажмите Download: Format `FBX Binary (.fbx)`, Skin `With Skin`, Pose `T-pose`. Сохраните как `viking.fbx`.
4. **Анимация покоя.** Найдите в Mixamo "Breathing Idle" или "Idle". Download: `FBX Binary`, Skin `Without Skin`, 30 fps. Сохраните как `idle.fbx`.
5. **Танцы.** Найдите 1-3 танца, например "Silly Dancing", "Hip Hop Dancing", "Rumba Dancing", "Northern Soul Spin". У каждого включите галочку In Place, если она есть. Download: `FBX Binary`, `Without Skin`. Сохраните как `dance.fbx`, `dance2.fbx`, `dance3.fbx`.
6. Положите все файлы сюда:

```
public/assets/models/custom/
├─ viking.fbx
├─ idle.fbx
├─ dance.fbx
├─ dance2.fbx   (необязательно)
└─ dance3.fbx   (необязательно)
```

7. Перезапустите `npm run dev`. В сцене появятся ваши викинги: в тишине анимация idle, под музыку танцы. Скорость танца подстраивается под темп. Каждый викинг танцует свой танец, если их несколько.
8. Допишите автора модели и ссылку в `CREDITS.md`. Для CC-BY указание автора обязательно.

Вариант с GLB: если вы собрали модель с анимациями в Blender, экспортируйте её в `public/assets/models/custom/viking.glb`. Клип покоя должен содержать в названии "idle", танцы - "dance".

Анимации Mixamo можно бесплатно использовать в своих проектах, в том числе в опубликованных, но нельзя распространять как отдельный набор файлов. Модель смотрит в сторону оси +Z и подгоняется по росту автоматически.
